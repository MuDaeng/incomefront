# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Frontend for the **income** dividend-portfolio API (NestJS backend: https://github.com/MuDaeng/income). Vite 8 + TypeScript, MUI 9 (`@mui/material`, `@mui/x-charts`, `@mui/x-date-pickers`), TanStack Query 5, React Router 7, dayjs. UI text is Korean.

## Working rules (always apply)

- **Reply in Korean** — progress updates, questions, final reports. Code identifiers and technical terms stay as-is.
- **Git branch strategy.** The default branch is `master`. Commit only when asked.
  - "커밋해줘" → create a short-lived branch off `master` (`feature/<topic>`, `fix/<topic>`, or `docs/<topic>`) and commit there. Never commit directly on `master`, even if the request says "커밋하고 master에 푸시해줘": commit on a branch first, then merge.
  - "머지하고 push하고 브랜치 삭제해줘" (or a request to push to `master`) → `git merge --ff-only <branch>` into `master`, `git push origin master`, then delete the branch locally (`git branch -d`) and on the remote if it was pushed. If `master` has moved and fast-forward fails, stop and ask instead of creating a merge commit.
  - After committing, offer the merge/push/delete step; don't run it unasked.
  - `.env.production` is committed (it holds only the public `VITE_API_URL`; never put secrets in it — `VITE_*` values are bundled into the client anyway). Never commit `.env.local` / `.env.*.local` or `claude-output.md` (gitignored). IDE files (`.idea/`) stay out of commits.
- **Conversation log: `claude-output.md`** at the repo root (gitignored, never committed). The user's terminal has no scrollback, so they read the conversation in this file in WebStorm.
  - After **every** turn, append the user's message **verbatim** as a `>` quote under `## 사용자`, then the reply exactly as printed in the terminal under `## Claude`. Newest at the bottom.
  - Clarifying questions and answers go under `## Claude (질문)` / `## 사용자 (답변)`. Short replies are logged too.
  - **Leave out git turns entirely**: commit, push, merge, branch-delete and PR requests and their replies are not logged — neither the request nor the result.
  - Group each session's turns under `# 대화 기록: <topics> (<YYYY-MM-DD>)`, separated from the previous session by `---`.
  - Still print the reply in the terminal as usual.
- **CI (`.github/workflows/ci.yml`)** runs on every push to `master` and every PR: `npm ci`, `npx tsc --noEmit -p .`, `npm run lint`, `npx vitest run`, `npm run build` (Node 22). Lint runs with `--max-warnings 0`, so ESLint warnings fail CI — keep lint warning-free.
- **GitHub Actions (`@claude` on issues/PRs, `.github/workflows/claude.yml`).** Only the repo owner/members/collaborators can trigger it. When running there, skip the `claude-output.md` log, commit on the `claude/issue-…` branch the action created (never push to `master`), and run the type-check, tests and build before committing. The workflow needs the `CLAUDE_CODE_OAUTH_TOKEN` repo secret and the Claude GitHub App installed on this repo.

## Commands

- `npm start` — dev server on http://localhost:3000. Backend is expected at `VITE_API_URL` (default `http://localhost:8080`, set locally in the gitignored `.env.local`; there is no `.env`). If port 3000 is already taken (the user often has a dev server running), don't kill that process — start another instance with `npm start -- --port 3001` (the config sets `strictPort`, so it fails instead of picking another port), keeping in mind that Google login only redirects back to the backend's `FRONTEND_URL` (normally 3000).
- `npm run build` — `tsc --noEmit` then `vite build` into `build/` (`vite.config.ts` `outDir`; `vercel.json` sets `framework: vite`, `buildCommand: npm run build` (overrides the old CRA `react-scripts build` command in the incomefront project settings), `outputDirectory: build` and the SPA rewrite to `/index.html` that deep links like `/auth/callback` need). Env: Vite's default `VITE_` prefix, read as `import.meta.env.VITE_*` (typed in `src/vite-env.d.ts`; the CRA-era `REACT_APP_API_URL` was renamed to `VITE_API_URL`, so the Vercel project env must use the new name too). Unlike CRA, Vite gives `.env.production` precedence over `.env.local`, so a local build points at `https://api.mudaeng.online` (use `.env.production.local` to override). The build does **not** run ESLint — run `npm run lint` before committing.
- `npm run lint` — ESLint 9 flat config (`eslint.config.js`: `@eslint/js` + `typescript-eslint` recommended, `react-hooks`, `import/first`), `--max-warnings 0`.
- `npx tsc --noEmit -p .` — type-check only (faster than a build). Covers `src/`, `test/` and `vite.config.ts`.
- `npx vitest run` — run tests once (`npm test` is watch mode). Single file: append its path (e.g. `test/lib/format.test.ts`); single test: append `-t "<name>"`.
  - **Test files never sit next to source.** Tests live in `test/` beside `src/`, mirroring the `src/` path: `src/lib/format.ts` → `test/lib/format.test.ts`. Import the code under test relatively through `src` (e.g. `../../src/lib/format`). `vite.config.ts` `test.include` only matches `test/**`, so a `*.test.ts` placed under `src/` will **not** run. The setup file is `src/setupTests.ts` (jest-dom matchers).
  - Vitest runs with `globals: true` (`describe`/`it`/`expect`/`vi` need no import; tsconfig `types` has `vitest/globals`). Mock types come from `vitest` (`import type { Mock, MockInstance } from 'vitest'`). Use `vi.*`, not `jest.*`.
  - **Page tests** live in `test/pages/<Page>.test.tsx` and render the real page with the real query hooks. Each file replaces only `request` at the top: `vi.mock('../../src/api/client', async (importOriginal) => ({ ...(await importOriginal<object>()), request: vi.fn() }));`, then `mockApi({ 'GET /balance': …, 'PATCH /accounts/1/type': … })` (`test/testUtils.tsx`; a value, a function of the request options, or an `apiError(status, msg)`; unknown requests fail) and `requestCalls(method, path)` to assert `query`/`body`. `renderPage(ui, { route, path, outletContext })` wraps the app providers, a `MemoryRouter` and the `useLayout()` outlet context. Response builders live in `test/fixtures.ts`. MUI selects: `fireEvent.mouseDown(combobox)` then click the `option` (use `findByRole` when options load async; `selectOption` helper otherwise).
  - `vite.config.ts` `test.alias` maps `@mui/x-charts/*` to the stub `test/mocks/xCharts.tsx` (charts need layout that jsdom lacks — page tests check numbers/text, not charts). `testTimeout` is 20 s because page tests render real MUI dialogs.

## Architecture

Folder roles: `src/api/` (backend calls), `src/auth/`, `src/components/` (shared UI and dialogs), `src/pages/` (one file per route), `src/lib/` (pure helpers).

- **Pages and components never call `fetch` or `request` directly.** Every backend call goes through a hook in `src/api/queries.ts`; add a new endpoint there (hook + `queryKeys` entry + response type in `types.ts`).
- **Mutations invalidate through the shared key prefix**, not by refetching individual queries from components.
- **Pure logic (formatting, validation, date math) goes in `src/lib/`** so it can be unit-tested from `test/lib/`.

**API layer (`src/api/`)**
- `client.ts` — the only `fetch` wrapper. The access token lives in memory only; the refresh token is an httpOnly cookie (`path=/auth`) set by the backend, so every request uses `credentials: 'include'`. On a 401 it calls `/auth/reissue` once and retries. `/auth/access` and `/auth/reissue` share a single in-flight promise, because the backend rotates the refresh token on reissue — two concurrent reissues would make the second one 401 and log the user out. Nest error bodies (`message: string | string[] | issue[]`) are normalized into `ApiError.message`.
- `types.ts` mirrors the backend DTOs. **All amounts, quantities and rates are decimal strings** (KRW integers, USD 6 decimals, rates in % with 2 decimals). Convert with `toNumber` / the `format*` helpers in `src/lib/format.ts` only at display time.
- `queries.ts` — every React Query hook and the `queryKeys` factory. All balance-related keys share the `['balance']` prefix; the register and sell mutations invalidate that prefix so dashboard, purchases, dividends and returns refresh together.

**Auth flow (`src/auth/AuthProvider.tsx`)**
Google login is a full-page redirect to `${API_URL}/auth/google`. The backend redirects back to `/auth/callback` (`AuthCallbackPage`), which calls `completeLogin` → `/auth/access` → `/auth/me`. On normal app load the provider tries the same silent login, except on the callback path. The backend has no logout endpoint and the cookie survives, so logout sets the `income.loggedOut` localStorage flag to suppress auto-login until the next explicit login.

**Routing / layout**
`App.tsx` wires the providers (Theme → date-picker Localization → QueryClient → Notifier → Router → Auth). Protected routes sit under `RequireAuth` → `Layout`. `Layout` owns the global "매수 등록" dialog and exposes it to pages through outlet context (`useLayout().openRegister(security?)`). `useNotify()` shows snackbars. Render errors are caught by `ErrorBoundary` (`src/components/ErrorBoundary.tsx`): one around the whole app (`variant="app"`, reload only) and one around the `Layout` outlet keyed by pathname, so a crashing page keeps the menu and clears when you navigate. It does not catch event-handler/async errors; query errors still go through `ErrorAlert`.

**Shared conventions**
- **XSS rules.** Never use `dangerouslySetInnerHTML`, `innerHTML`/`outerHTML`/`insertAdjacentHTML`, `document.write`, `eval`/`new Function`, or `srcDoc`. Never put server, external-API or user data into `href`, `src`, `action` or `window.location` (a `javascript:` URL runs code); only fixed URLs or route paths built by helpers like `securityDetailPath`. Render such data as React text (it is escaped), e.g. batch `result` inside a `<pre>`. Don't store tokens in `localStorage`/`sessionStorage` (the access token stays in memory).
- **CSP / security headers** live in `vercel.json` (production only): `script-src 'self'` (the Vite build emits only an external module script; never add inline `<script>` to the root `index.html`), `style-src 'self' 'unsafe-inline' https://cdn.jsdelivr.net` (emotion inline styles + Pretendard CSS), `font-src` jsdelivr, `connect-src 'self' https://api.mudaeng.online`, `frame-ancestors 'none'`. Adding an external script, font, image host or API origin means adding it to the CSP too, or the browser blocks it.
- `DateRangeBar` holds the period presets (`PRESETS` in `DateRangeBar.tsx`). Each page picks its own preset list, ordered from shortest to longest period (기간 수익률 starts with `last1d` "하루" = yesterday ~ today, because `from` = `to` would measure against the same day's close, and ends with `sinceStart` "전체" = no `from` ~ today; 배당금 keeps `today` and ends with `all` = no `from`/`to`). Dates travel as `'YYYY-MM-DD'` strings, which also compare correctly as strings.
- Korean market colors: gains are red (`RISE_COLOR`), losses are blue (`FALL_COLOR`). Use `ProfitText` / `profitColor`, not MUI `success` / `error`.
- Client-side validation mirrors the backend Zod schemas: positive decimal strings (`isPositiveDecimal`), and sale date ≥ purchase date. A purchase date with no daily price is rejected by the backend, so the register dialog checks `/daily-securities` for that date first.
- Chart colors come from `src/lib/chart.ts` (`KRW_COLOR` for domestic, `USD_COLOR` for US).
- The security detail price chart is a hand-drawn candlestick (`CandleChart`): MUI X Charts community has no OHLC series, so it renders on `ChartsContainer` with a band x-axis and a hidden `line` series (needed for the axis tooltip). Candles use `RISE_COLOR` / `FALL_COLOR`; daily→weekly aggregation lives in `src/lib/candles.ts`.

## Backend contract notes

- The backend's CORS origin is its `FRONTEND_URL` env var. It must be `http://localhost:3000` for local login and cookies to work.
- `/balance/returns` takes optional `from`/`to` (backend date-range policy): omitted `from` = the whole history (every lot at cost, dividends from the beginning), omitted `to` = today (KST). The response `from` is null when omitted (not the first purchase date) and `to` is always the valuation date. `ReturnsPage` shows "처음부터" for a null `from`; its `MonthlyTrendSection` then requests the last 120 months and drops the leading empty months (`trimLeadingEmptyMonths`, `src/lib/months.ts`). Its `profit`/`returnRate` (and the after-tax ones) are a **period return against `baseAmount`, not the cost**: lots bought before `from` count at the latest close on or before `from` × quantity (USD × `startExchangeRate`), lots bought in the period (or with no usable start close) at cost. `purchaseAmount` stays the real cost. Extra fields: `baseAmount` (evaluation total, total items/total), `krwBaseAmount`/`usdBaseAmount`/`startClosingPrice`/`startPriceDate` (evaluation items; start close null = cost used), top-level `startExchangeRate`/`startExchangeRateDate`. KRW closes before 15:30 KST use the previous day. USD closes are looked up one day earlier (`from − 1`, `to − 1`; bars are stored by US trading date and close the next morning KST), so 하루 (yesterday ~ today) shows last night's US session; `/balance/monthly` uses the same rule. `ReturnsPage` shows 원금 and 기준금액 side by side and never computes 평가손익 as evaluation − purchase (use the server `profit`, or evaluation − `baseAmount` per total item).
- `/balance/dividends` accepts either or neither (omitted = unbounded; the response `to` is always a date, today when omitted, while `scheduled` still holds later payments; `/daily-securities` responds the same way). Its `months`/`total` hold only dividends paid by today (KST); ones paid after today come separately in `scheduled: { total, items }` (same summary/item shape, payment-date order), so `/balance/returns` and `/balance/monthly` never count unpaid dividends. The 배당금 page shows `scheduled` as a "지급 예정" card at the top of the 월별 내역 tab and in the card footers.
- **배당금 page tabs**: the header, `DateRangeBar` and the three summary cards stay on top; below them `Tabs` show one section at a time — 월별 내역 (default: 지급 예정 card, monthly chart, month accordions), 배당금 순위, 배당 지표 (`DividendMetricsSection` + recovery card). The tab lives in the URL query `?tab=ranking|metrics` (`useTabParam`, `src/lib/useTabParam.ts`; the default tab removes the key), and only the open tab is rendered, so `/balance/dividend-metrics` and `/balance/monthly` are requested only when 배당 지표 is opened. **배당금 순위** has no API of its own: `rankDividends` (`src/lib/dividendRanking.ts`) sums the period's paid items (`months`, `scheduled` excluded, following the 세전/세후 toggle via `dividendItemView`) per security — count, amount in the security currency, KRW amount (items without a rate are left out of the KRW sum) and share of the KRW total (2 decimals truncated) — sorted by KRW amount desc, then name; rows link to the detail page (`DividendRankingTable`).
- Selling a purchase lot is identified by `(securityId, purchaseDate, sequence)`, taken from `/balance/purchases`.
- `POST /balance` takes an optional `exchangeRate` (KRW per USD; ignored for KRW). Omitted → the backend stores the purchase-date USD rate. There is no GET endpoint for exchange rates, so the register dialog leaves the field empty instead of pre-filling it. `/balance/purchases` returns the stored rate with `exchangeRateDate: null`, or the fallback rate with its date; its `price` is already cut to 2 decimals (`ROUND_DOWN`).
- `PATCH /balance/purchases` (body `{ securityId, purchaseDate, sequence, exchangeRate }`) changes one lot's stored purchase exchange rate, sold lots too (`useUpdateExchangeRate`, `EditExchangeRateDialog` on the detail page). `exchangeRate: null` clears it so queries fall back to the purchase-date rate; the key is required (omitting it is 400) and KRW securities are 400.
- **Rate limiting (429)**: per IP per minute, 100 requests by default, 10 for `/auth/google`, `/auth/google/callback`, `/auth/access`, `/auth/reissue`, 30 for `GET /daily-securities`. `apiErrorMessage` (`src/lib/apiError.ts`) turns any 429 into a Korean "try again in a minute" message (Nest's body says "ThrottlerException: Too Many Requests"). A 429 from `/auth/reissue` must not log the user out (`request()` rethrows it); a 429 on silent login sets `autoLoginError`, shown on the login page. The register dialog debounces the purchase-date price lookup for the same reason. Query retries already skip 4xx.
- The backend has no bulk import (data collection) endpoints anymore (`/daily-securities/import*`, `/exchange-rates/import` were removed; collection is batch-only) — don't add UI for them. The one-time `POST /admin/domestic-daily-prices/import` was removed too, along with its button, dialog and hook.
- The backend keeps one refresh-token session per login/device, so logging in elsewhere doesn't log this browser out. Reissue still rotates that session's refresh token, so the single in-flight `/auth/access`·`/auth/reissue` promise in `client.ts` stays necessary.
- `GET /balance/monthly?from&to` (`useMonthlyBalance`, `MonthlyTrendSection` at the bottom of the 기간 수익률 page; it converts that page's `YYYY-MM-DD` range with `monthsForDateRange`, capping `to` at the current month and the span at 120 months, and skips the call when nothing is left): both `YYYY-MM` and required, `to` at most the current month, at most 120 months (else 400). Months come oldest first; each has a `total` and per-security `items`, all KRW. The valuation date is the month's last day (today for the current month). `dividendAmount` is **cumulative from the very first dividend**, not per month. Sold securities stay in `items` with quantity 0 while they have dividends. The range conversion and the return-rate helper live in `src/lib/months.ts`.
- **Accounts (계좌)**: holdings belong to an account (`{ id, securityCompany, accountType }`, `id` = per-user sequence; `accountType` `NORMAL`·`ISA`·`IRP`·`PS` = 일반·ISA·IRP·연금저축, labels in `src/lib/account.ts`, must match the backend `libs/common/src/user/account-type.enum.ts`). Brokers (`SecurityCompany`, Korean brokers + `ETC`) stay in `src/lib/securityCompany.ts` and must match `libs/common/src/user/security-company.enum.ts`; each has a distinct `color` (major ones close to their brand color). API: `GET /accounts?securityCompany` → `{ accounts }` (id order; `useAccounts`, key `['balance','accounts',…]` because registering can create an account), `POST /accounts` `{ securityCompany, accountType? }` (201, default `NORMAL`; `useCreateAccount`), `PATCH /accounts/:id/type` `{ accountType }` (`useUpdateAccountType`), `DELETE /accounts/:id` (204; 400 while it still has lots, sold ones included; `useDeleteAccount`). These live on the 계좌 관리 page (`AccountsPage`, `/accounts`, side menu). `POST /balance` requires `securityCompany` and takes an optional `accountId` (omitted → that broker's first account, else the backend creates a `NORMAL` one); the register dialog shows an account select under the broker when the broker has accounts (otherwise a note that a new 일반 account will be created) and starts from the page's account filter or else the last broker/account used (`income.lastAccount` in localStorage, `initialRegisterAccount`). An optional `accountId` query filters `GET /balance`, `/balance/purchases`, `/balance/dividends`, `/balance/returns`, `/balance/monthly` and `/balance/dividend-metrics` (omitted = all accounts); dividends then use that account's held quantity only. Every page keeps the filter in the URL query `?accountId=` via `useAccountParam` (`src/lib/useAccountParam.ts`), renders it with `AccountSelect` ("전체 계좌" + every account from `GET /accounts`) and passes it to detail links with `securityDetailPath` (`src/lib/account.ts`). Account names: `accountLabel` ("토스증권 · ISA") and `accountShortLabel` ("토스", "토스 ISA"); a ` #id` suffix is added only when the same broker+type exists more than once. `/balance/purchases` items carry `accountId`, `securityCompany`, `accountType`; the detail table shows them as `AccountChip` (broker-tinted chip). `PATCH /balance/purchases/account` (body `{ securityId, purchaseDate, sequence, accountId }`, sold lots too, sequence unchanged; `useUpdatePurchaseAccount`, `MovePurchaseAccountDialog` "계좌 이동") moves one lot to another of the user's accounts (e.g. transfer to another broker); it lists existing accounts only and links to 계좌 관리 to create one. `sequence` is still numbered per (security, purchaseDate) across accounts, so `(securityId, purchaseDate, sequence)` still identifies a lot. While filtered, the detail page doesn't treat a single remaining lot as the security's last one. `GET /balance/security-companies` and `PATCH /balance/purchases/security-company` no longer exist.
- `DELETE /balance/purchases?securityId&purchaseDate&sequence` (204) deletes one mis-registered lot, sold ones too (`useDeletePurchase`). When it was the security's last lot the backend also drops it from the holdings, so the detail page navigates back to `/`. Remaining lots keep their sequences.
- `POST /balance/sale/bulk` (body `{ securityId, securityCompany, accountId?, amount, saleDate }`; `useBulkSellBalance`, `BulkSellDialog` "계좌별 일괄매도" from the detail page's "일괄매도" button) sells `amount` from that account's unsold lots bought on or before `saleDate`, newest purchase first (LIFO). The dialog offers the accounts in `accountAmounts` and sends both the account's broker and id. If they hold less than `amount` the backend returns 400 and sells nothing; the dialog only checks the account's total held quantity and shows the 400 message for the date case.
- `POST /balance/toss` (body `{ accountId?, transactionList: TossTransaction[], confirmedTransfersOut? }`, JSON body limit 1mb; `useBulkRegisterToss`, `TossImportPage` at `/toss-import`, "일괄등록" button under "매수 등록" in the side menu) rebuilds one Toss account in one transaction (`accountId` omitted → the first TOSS account, else a new `NORMAL` one): deletes all its lots (sold ones too), registers `BUY`·`SECURITIES_TRANSFER_IN` (no daily-price check; a transfer-in uses the last close on or before its date), then sells `SELL` and confirmed transfers out oldest sale first, each newest purchase first (LIFO). Not enough holdings → 400 and everything rolls back. **Stock lending**: a `SECURITIES_TRANSFER_OUT` is treated as lent out (not sold) unless its key is in `confirmedTransfersOut`, and a later transfer in of the same ISIN pays it back first (only the excess is bought). Returns `{ accountId, deletedCount, boughtCount, soldCount, skipped: [{ transactionType, isinCode, reason }], lentTransfers: [{ key: { isinCode, settlementDate, quantity, index }, remainingQuantity }] }` (skipped: cancellations, unknown ISIN, missing quantity/price, transfer-in without a price, 빌려주기 반환/출고(반환됨)). The input step has a Toss account select ("첫 토스증권 계좌"/"새 일반 계좌" when none chosen); the result step lists `lentTransfers` with checkboxes, and "선택한 출고 n건을 매도로 다시 등록" re-posts the same transactions with the response's `accountId` and the accumulated `confirmedTransfersOut` (keys sent back exactly as received; `tossTransferKeyId`/`mergeTransferKeys`). The page takes a file or pasted JSON, previews it client-side (no server call) and needs a confirm checkbox. A broker select at the top is fixed to 토스증권 (disabled, "다른 증권사는 추후 출시 예정입니다.") so other brokers can be added later. Parsing keeps only the 13 fields the backend reads; the trade date is `settlementDate` − 2 KRX trading days for every trade (backend `apps/api/src/balance/toss-trade-date.ts` → `security/trading-day.ts`, using stored trading days); the preview's `tossTradeDate` counts weekdays only (no holiday list API), which must match the backend's weekday fallback, and the page notes that a holiday can make the server date earlier. Helpers live in `src/lib/tossImport.ts`.
- **Show `symbol`, never `securityId`, on screen.** `securityId` (ISIN) is only for keys, routes and requests. `GET /balance` items carry `symbol` (shown under the name on the dashboard); the detail page header shows `security.symbol`.
- The detail page's 평균 매수가 card shows the current price (last close of the past month from `/daily-securities`, since `/balance/purchases` has no price) and its change against the average.
- **User rules / admin**: the access token payload is `{ sub, rules }` (`rules`: `'user' | 'admin'`; tokens issued before rules existed have none). `/auth/me` has no rules, so `AuthProvider` decodes the token returned by `/auth/access` (`isAdminToken`, `src/lib/jwt.ts`, no signature check — display only) into `isAdmin`. Role changes apply from the next token issue (re-login). Admins are granted only in the backend DB. `Layout` shows a single "관리자" menu (`ADMIN_NAV`, `/admin`, highlighted on every `/admin/*` path) only when `isAdmin`; the server still guards the APIs. `/admin` renders `AdminLayout` (`src/pages/AdminLayout.tsx`): tabs on top (`ADMIN_TABS`: 배치 이력 `/admin/batches`, 시세 조회 이력 `/admin/price-searches`, 토큰 갱신 이력 `/admin/client-tokens`) and the selected page in an `Outlet` (nested routes in `App.tsx`; each tab has its own URL, the selected tab follows the path, and `/admin` redirects to `/admin/batches`). A new admin page means a route under `admin` plus an `ADMIN_TABS` entry.
- `GET /admin/security-searches/price` (JWT + admin, no params, no paging; `usePriceSearches`, `AdminPriceSearchPage` at `/admin/price-searches`) returns every `security_search` row of type PRICE as `[{ securityId, name, lastSearchDate, createdAt, updatedAt }]`, newest `lastSearchDate` first (then `securityId`). A row is written when a domestic (KRW) security lookup tops up one day of prices from KIS; `lastSearchDate` is the price date checked (yesterday before 15:30 KST, today after). `name` is null if the security master lacks it. The response has no `symbol` yet (the type keeps it optional and the page shows it when present), so the page shows the name only and never the `securityId`; its name/symbol search is client-side (`filterPriceSearches`, `src/lib/priceSearches.ts`).
- `GET /admin/client-tokens` (JWT + admin, no params; `useClientTokens`, `AdminClientTokenPage` at `/admin/client-tokens`) returns `[{ clientType, updatedAt }]` (`clientType` `TOSS`·`KAKAO`·`NAVER`·`KIS`, must match the backend `libs/common/src/client/client-type.enum.ts`), newest `updatedAt` first (then `clientType`). The token value itself is never returned. `updatedAt` changes only when a token is newly issued and saved (`KisClient`), not on calls that reuse the stored token. Labels and the elapsed-time text live in `src/lib/clientTokens.ts` (unknown types show the raw value).
- `GET /admin/batch-histories?name&status&limit` (JWT + admin, else 403 "관리자만 사용할 수 있습니다."; `limit` 1–100, default 20; `status` `RUNNING|SUCCESS|FAILED`; `useBatchHistories`, `AdminBatchPage` at `/admin/batches`) returns `[{ id, name, status, startedAt, finishedAt, durationMs, result }]`, newest first. Job names in the page's filter (`JOBS`) must match the backend `apps/batch/src/scheduler/batch.jobs.ts`. A row left `RUNNING` means running or the process died.
- `GET /dividends?securityId` (public, no JWT, 30/min like `/daily-securities`, unknown security → 404; `useSecurityDividends`, `DividendHistoryCard` on the detail page) returns `{ security, months: [{ month: 'YYYY-MM', amount, count }] }`: per-share cash dividends summed by payment month, only months with payments, oldest first, upcoming payments included. It is independent of holdings, so its key is not under `['balance']`. Zero-filling and the trailing-12-month sum live in `src/lib/dividends.ts`.
- **Dividend tax (세전·세후)**: `/balance/dividends` and `/balance/returns` return after-tax fields next to the unchanged pre-tax ones. Only `NORMAL` accounts are taxed (KRW 15.4%, USD 15% US withholding); ISA·IRP·PS have after tax = pre-tax. Dividend items: `taxAmount`, `afterTaxAmount` (security currency), `afterTaxUsdAmount`, `afterTaxKrwAmount` (null without a rate); summaries: `afterTaxKrwAmount`/`afterTaxUsdAmount`/`afterTaxUsdKrwAmount`/`afterTaxTotalKrwAmount`. Returns: dividend items/total `afterTaxUsdAmount`/`afterTaxKrwAmount`, total items/total `afterTaxDividendAmount`/`afterTaxTotalAmount`/`afterTaxProfit`/`afterTaxReturnRate`. Both pages have a `TaxModeToggle`; the choice is remembered in localStorage `income.taxMode` (`useTaxMode`, shared by both pages, default 세전); field selection goes through the view helpers in `src/lib/dividendTax.ts`, never by picking `afterTax*` fields in pages. `/balance/monthly` and `/balance/dividend-metrics` stay pre-tax (the monthly trend subheader says so).
- **Ex-dividend date**: `/balance/dividends` items carry `exDividendDate` (nullable). The backend counts a dividend for lots bought before the ex-dividend date and sold on or after it (KRW ex-dates are computed from the record date with the KRX trading calendar, USD come from Massive); rows saved before the column existed have null and fall back to the record-date (`noticeDate`) rule. The 배당금 page shows both dates, `-` with a tooltip when null.
- `GET /balance/dividend-metrics?accountId` (`useDividendMetrics`, key under `['balance']`) returns pre-tax metrics for the securities held today: per item `trailingPerShare`/`paymentCount` (paid in the last 12 months), `previousPerShare`/`previousPaymentCount`, `growthRate` (null without a previous year) and `growthBasis` (`TOTAL` = 12-month sums; `PER_PAYMENT` = per-payment averages, only for KRW securities whose first cash dividend falls inside the previous 12 months with fewer payments there — listed ~1 year ago; shown via `growthBasisNote` in the detail box as "상장 1년 미만 · 회당 평균 a → b" and as a "회당 평균" caption in `DividendMetricsSection`), `annualDividend`/`krwAnnualDividend` (trailing × current quantity), `krwPurchaseAmount`, `closingPrice`, `krwEvaluationAmount`, `yieldOnCost`, `currentYield` (percent strings, nullable), plus a `total`. It is shown in `DividendMetricsSection` in the 배당금 page's 배당 지표 tab (today-based, independent of the page's date range), as the "예상 연배당" card on the dashboard, and as metric boxes in the detail page's `DividendHistoryCard` (via `findMetricsItem`; hidden when not held). Helpers live in `src/lib/dividendMetrics.ts`; unsigned percentages use `formatPercent`.
- **배당으로 원금 회복** (no backend API of its own): for held securities whose `totalAmount` (evaluation + cumulative dividends) from `GET /balance/monthly` for the current month alone is below `purchaseAmount`, months to recover = ceil(loss ÷ `krwAnnualDividend` × 12) from `/balance/dividend-metrics` (null when there is no dividend). Shown as `DividendRecoveryCard` under 종목별 배당 지표 (whenever something is held; an empty-state message when nothing is at a loss, `ErrorAlert` when the monthly call fails) and as a full-width box under the detail page's metric boxes (held securities only; "배당 포함 손실이 없어요 (+gain)" when not at a loss, an error line when the monthly call fails). Caveats in `RECOVERY_NOTE`: assumes the current price and dividends hold, pre-tax, and `dividendAmount` also counts dividends paid on lots already sold. Helpers live in `src/lib/dividendRecovery.ts`.
- `GET /balance` items and the `GET /balance/purchases` response carry `accountAmounts` (`[{ accountId, securityCompany, accountType, amount }]`, unsold lots only, accounts with quantity > 0, account id order, after the `accountId` filter); `/balance/purchases` also has a total `amount`. `AccountAmountChips` (`src/components/SecurityCompanySelect.tsx`) renders them as broker color chips ("토스 3", "토스 ISA 2") under the quantity on the dashboard and in the detail page's 보유 수량 card, even for a single account; the dashboard passes `hideSingleAmount`, so a single account shows only its name.
